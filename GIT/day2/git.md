# Git & GitHub 추가 핵심 개념 정리

## 1. Git 내부 구조와 상태 관리
* **HEAD (헤드)** : 현재 내가 작업 중인 브랜치의 가장 최신 커밋을 가리키는 위치 포인터.
* **Git의 3가지 작업 영역** : 파일을 실제로 수정하는 **Working Directory**, 커밋할 파일들을 선별해 올려두는 **Staging Area**, 커밋이 확정되어 버전으로 영구 기록되는 **Repository**로 구성.
* **`.gitignore`** : 환경 변수(`.env`), 빌드 결과물, 로그 파일 등 Git 버전 관리 추적에서 제외할 파일이나 폴더 목록을 지정하는 설정 파일.
* **커밋 메시지 작성 규칙** : 한 커밋에는 하나의 작업만 담고, 무엇을 왜 바꿨는지 한눈에 알 수 있도록 동사(Add, Fix, Refactor 등)로 시작하여 간결하게 작성한다.

## 2. 원격 저장소 연결 및 협업 워크플로우
* **`git remote`** : 로컬 저장소에 GitHub 원격 저장소 주소를 연결(`git remote add origin 주소`)하거나 연결된 목록을 확인(`git remote -v`)하는 명령어.
* **Clone vs. Fork** : **Clone**(`git clone`)은 원격 저장소의 코드를 내 로컬 컴퓨터로 그대로 복제해 오는 것이고, **Fork**는 푸시 권한이 없는 타인의 원격 저장소를 내 GitHub 계정으로 복제해 오는 기능.
* **Pull Request (PR)** : 자신이 작업한 브랜치의 변경 사항을 원본 저장소(주로 `main` 또는 `develop`)에 병합해 달라고 요청하고 검증받는 단계.
* **Code Review (코드 리뷰)** : PR을 병합하기 전에 팀원들이 코드를 함께 검토하여 버그를 예방하고 코드 품질과 팀 규칙을 유지하는 과정.
* **Issue (이슈)** : 프로젝트에서 해야 할 일(To-do), 버그 리포트, 새로운 기능 요청 등을 등록하고 PR과 연결하여 관리하는 기능.

## 3. 이력 조회 및 비교 명령어
* **`git log`** : 저장소에 기록된 커밋 이력들을 시간순으로 확인하며, `--all --graph` 옵션을 붙이면 브랜치 흐름을 시각적으로 볼 수 있다.
* **`git show`** : 특정 커밋 하나를 지정하여 해당 커밋의 메타데이터(작성자, 날짜, 메시지)와 실제 코드 변경 내역을 상세히 확인하는 명령어.
* **`git diff`** : 작업 디렉토리와 스테이징 영역(`git diff`), 스테이징 영역과 최신 커밋(`git diff --staged`), 또는 서로 다른 두 커밋 간의 코드 차이점을 비교하는 명령어.
* **`git blame`** : 특정 파일의 각 코드 줄을 누가, 언제, 어떤 커밋에서 작성하거나 수정했는지 줄 단위로 추적하는 명령어.

## 4. 임시 저장 및 이력 수정/복구 명령어
* **`git stash`** : 아직 커밋하기 애매한 현재 작업 내용들을 임시 공간에 잠시 치워두는 명령어로, 급하게 다른 브랜치로 이동해야 할 때 사용하고 `git stash pop`으로 다시 꺼냄.
* **`git commit --amend`** : 새로운 커밋을 추가하지 않고 가장 마지막에 작성한 커밋의 메시지를 수정하거나 누락된 파일을 덮어씌워 고치는 명령어.
* **`git reset`** : 브랜치의 기준(HEAD)을 과거의 특정 커밋으로 되돌려 이후 이력을 지우는 명령어. (`--soft`: 커밋만 취소 / `--mixed`: 스테이징까지 취소 / `--hard`: 실제 작업 파일 변경 내용까지 모두 삭제)
* **`git revert`** : 과거의 특정 커밋 내용을 취소하는 **새로운 커밋**을 생성하는 명령어로, 기존 커밋 히스토리를 지우지 않고 보존하므로 협업 브랜치에서 안전하게 롤백할 때 사용.
